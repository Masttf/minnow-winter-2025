### 第一部分：TCPSender 的宏观视角与使命

`TCPSender` 的核心使命是扮演一个“翻译官”的角色：它将上层应用传来的、连续不断的**字节流 (`ByteStream`)**，“翻译”成一个个离散的、遵循 TCP 协议规则的**数据段 (`TCPSenderMessage`)**，并确保它们能够**可靠地、按顺序地、不压垮对方地**送达接收方。

为了完成这个使命，它必须解决三大挑战：
1.  **可靠性 (Reliability):** 保证发送的数据不丢失。（通过 ACK 和重传机制解决）
2.  **有序性 (In-Order):** 保证接收方能按正确顺序重组数据。（通过序列号解决）
3.  **流量控制 (Flow Control):** 保证发送速度不会超过接收方的处理能力。（通过接收方通告的窗口大小解决）

### 第二部分：核心组件 (你的“武器库”和“记忆”)

在开始行动前，你的 `TCPSender` 需要一些内部变量来记住关键信息。这些就是它的“状态”。

*   **序列号管理:**
    *   `_next_seqno`: 一个 `uint64_t`，记录下一个**将要发送**的新字节的绝对序列号。
*   **窗口状态:**
    *   `_window_size`: 接收方通告的最新窗口大小。
    *   `_last_ackno`: 我方已知的、被对方成功接收的最后一个连续字节的下一个序列号。
*   **最重要的数据结构：未确认段队列**
    *   `_outstanding_segments`: 一个队列（`std::queue`）或列表，存放所有**已发送但未被完全确认**的 `TCPSenderMessage`。这是重传的依据。
*   **重传计时器（由变量模拟）:**
    *   `_initial_rto_ms`: 初始 RTO 值，恒定不变。
    *   `_current_rto_ms`: 当前的 RTO 值，会在重传时翻倍。
    *   `_timer_running`: 一个布尔值，表示计时器是否在“滴答作响”。
    *   `_time_elapsed`: 计时器启动后，已流逝的时间。
    *   `_consecutive_retransmissions`: 连续重传的次数。
*   **生命周期标志:**
    *   `_syn_sent`: 布尔值，记录是否已发送过 SYN。
    *   `_fin_sent`: 布尔值，记录是否已发送过 FIN。

### 第三部分：三大核心事件 (驱动 TCPSender 运作的引擎)

你的 `TCPSender` 是被动的，它只在三个特定事件发生时才行动。

#### 1. `push()` 事件：“引擎” - 尽力发送

*   **触发时机：** 由上级（`TCPConnection`）在**任何可能允许发送新数据**的时候调用（例如：应用来了新数据、ACK 打开了窗口）。
*   **核心目标：** **填满接收方的窗口**。
*   **详细逻辑流程：**
    1.  **处理 SYN (仅一次):** 检查 `!_syn_sent`。如果是，这是连接的开始。创建一个段，设置 `SYN=true`，并**尽可能捎带上第一批数据**。发送后，设置 `_syn_sent = true`。
    2.  **主发送循环:** 进入一个 `while` 循环，条件是 **“窗口有空间” AND “流中还有数据/FIN要发送”**。
        *   **计算段大小:** `payload_size = min(可用窗口空间, MAX_PAYLOAD_SIZE)`。
        *   **创建并发送段:** 从 `ByteStream` 读取 `payload_size` 字节，创建**一个** `TCPSenderMessage`，发送它。
        *   **记录在案:** 将这个段存入 `_outstanding_segments` 队列。
        *   **更新状态:** 增加 `_next_seqno`，减小“可用窗口空间”。
        *   **启动计时器:** 如果 `!_timer_running`，启动它。
    3.  **处理 FIN (仅一次):** 循环结束后，检查 `is_finished() && !_fin_sent && 窗口有空间`。如果满足，创建并发送一个（可能为空载荷的）FIN 段，存入队列，并设置 `_fin_sent = true`。
    4.  **零窗口探测(特殊规则):** 如果 `push` 开始时发现真实窗口为 0，则**跳过主循环**，但执行一次“假装窗口为1”的逻辑，发送一个**单字节**的探测段（如果流中还有数据的话）。

#### 2. `receive()` 事件：“反馈” - 学习与调整

*   **触发时机：** 从接收方收到了一个 ACK 报文。
*   **核心目标：** 根据 ACK 更新窗口状态，并清理已被确认的段。
*   **详细逻辑流程：**
    1.  **有效性检查:** 忽略那些旧的、无效的 `ackno`。
    2.  **更新窗口:** 用 ACK 报文里的新窗口值更新 `_window_size`。
    3.  **清理队列:** 这是关键！遍历 `_outstanding_segments` 队列，从队头开始，移除所有**被这个新 `ackno` 完全覆盖**的段。
    4.  **判断是否为新ACK:** 检查这个 ACK 是否确认了**新的**数据（即 `ackno > _last_ackno`）。
    5.  **如果是新ACK:**
        *   将 `_current_rto_ms` **重置**为 `_initial_rto_ms`。
        *   将 `_consecutive_retransmissions` **清零**。
        *   **管理计时器:**
            *   如果队列**变空**了，**停止**计时器 (`_timer_running = false`)。
            *   如果队列**还有段**，**重启**计时器（`_time_elapsed = 0`）。

#### 3. `tick()` 事件：“安全网” - 处理异常

*   **触发时机：** 外部模拟器告知时间流逝了 `ms_since_last_tick` 毫秒。
*   **核心目标：** 检查计时器是否超时，如果超时则认为数据丢失并重传。
*   **详细逻辑流程：**
    1.  **检查计时器:** 如果 `!_timer_running`，直接返回，无事发生。
    2.  **推进时间:** `_time_elapsed += ms_since_last_tick`。
    3.  **判断超时:** 检查 `_time_elapsed >= _current_rto_ms`。
    4.  **如果超时:**
        *   **重传:** 从 `_outstanding_segments` 队列的**队头**取出（但**不移除**）那个最早的段，然后重新发送它。
        *   **指数退避:** 如果窗口大小非零，`_current_rto_ms *= 2`。
        *   **增加计数:** `_consecutive_retransmissions++`。
        *   **重启计时器:** `_time_elapsed = 0`。

### 第四部分：串联起来的生命周期

1.  **连接建立:** 第一次 `push()` 调用发送 SYN 段，计时器启动。
2.  **数据传输:** 进入一个健康的循环：`push()` 发送数据填满窗口 -> `receive()` 收到 ACK 清理队列、打开窗口 -> `push()` 再次被调用填满新窗口... 这个循环中，`tick()` 在后台默默计时，一旦某个 ACK 丢失导致长时间没收到确认，`tick()` 就会触发重传。
3.  **连接关闭:** 应用关闭 `ByteStream` (`is_finished()`) -> `push()` 尝试发送 FIN（可能因窗口满而推迟） -> 最终 `push()` 成功发送 FIN -> `tick()` 和 `receive()` 继续工作，确保 FIN 被确认 -> 当确认 FIN 的 ACK 到达 `receive()`，`_outstanding_segments` 队列最终变空，计时器停止。`TCPSender` 的使命至此才完全结束。
